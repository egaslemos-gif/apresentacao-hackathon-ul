DO PROBLEMA AO PROTÓTIPO Hackathon · Comunidades Resilientes
Formação prática · 60 minutos

Do problema ao protótipo.

Design Thinking + UX + Prototipagem para transformar desafios comunitários em soluções testáveis.

Comunidades resilientes. Soluções inteligentes.
Pessoa → Problema → Evidência → Solução → Teste
01 · Abertura · 5 min

Começamos pela tecnologia?

🚫 Abordagem comum

“Vamos criar uma app para resolver a mobilidade.”

App → funcionalidades → tecnologia → procurar problema.

✓ Abordagem de design

“Quem está a ter dificuldade? Em que contexto? Qual é o impacto?”

Pessoa → contexto → problema → oportunidade → solução.

Analogia: construir uma ponte antes de saber quem precisa atravessar o rio é eficiência aplicada ao problema errado.
02 · Problem framing · 7 min

Problema ≠ solução.

“Precisamos de uma aplicação para ajudar pacientes.”

Melhor: “Pessoas de determinadas comunidades têm dificuldade em encontrar informação confiável sobre onde procurar atendimento.”

Fórmula

[Utilizador] enfrenta [problema] em [contexto], causando [impacto].

DESAFIO · 2 min

Escreva uma frase. Sem mencionar tecnologia.

03 · Empatia + UX · 8 min

Não desenhamos para “utilizadores”.

Quem?

Perfil, situação, restrições.

O que precisa?

Objetivo real, não funcionalidade.

O que faz hoje?

Comportamento atual e alternativas.

Problema
Procura informação
Tenta resolver
Resultado
Pergunta UX: “O que a pessoa está tentando realizar?” — e não “Que tela devemos criar?”
04 · Oportunidade · 8 min

Transforme o problema numa pergunta.

How Might We?

“Como poderíamos ajudar [quem] a [objetivo] em [contexto]?”

Mobilidade

Como poderíamos reduzir a incerteza durante a espera pelo transporte?

Saúde

Como poderíamos facilitar o acesso à informação sobre serviços de saúde disponíveis?

EXERCÍCIO · 2 min

Escreva apenas uma pergunta HMW. Se houver cinco, escolha uma.

05 · Ideação · 8 min

Primeiro divergimos. Depois convergimos.

Crazy 5

Não avalie enquanto gera.

Depois

Escolha uma hipótese de MVP.

Uma ideia não é uma solução validada. É uma hipótese.

10 · AI-assisted design

IA acelera. Não substitui evidência.

Use IA para

  • organizar hipóteses
  • gerar alternativas
  • estruturar fluxos
  • criar roteiros de teste
  • criticar um protótipo

Não delegue

  • o problema real
  • a voz do utilizador
  • evidências inexistentes
  • decisões éticas
  • validação
Prompt útil: “Com base apenas nestas evidências, separe factos, hipóteses e lacunas. Não invente dados.”

13 · Exemplo prático · Desafio

Do desafio ao prompt de prototipagem.

DESAFIO

“Como podemos melhorar a comunicação comunitária em situações de emergência?”

1 · Problema

Em situações de emergência, a comunidade pode ter dificuldade em comunicar rapidamente uma ocorrência e encontrar a pessoa ou serviço adequado para prestar apoio.

2 · Oportunidade

Como poderíamos facilitar o acesso rápido a uma rede comunitária de apoio, mantendo a experiência simples e acessível?

Hipótese de solução: um protótipo móvel que apresenta o estado da comunidade, uma ação SOS evidente e uma rede de contactos acessível em poucos passos.
14 · Exemplo prático · Prompt para IA

Agora transformamos o conceito em instrução.

Prompt

Crie um protótipo em HTML, CSS e JavaScript para um app comunitário chamado "Comunidade360" com: - Layout responsivo (desktop e mobile). - Cabeçalho com nome da comunidade e status ONLINE. - Seção de alerta com ícone de sirene animada em vermelho. - Texto explicativo: "Precisa de ajuda? Use o botão abaixo para aceder rapidamente à rede de apoio comunitário." - Botão SOS EMERGÊNCIA em vermelho, com animação de pulsar. - Ao clicar no botão, abrir modal com lista de contatos comunitários (nome + telefone). - Animações suaves (fade-in/out) para transições. - Design acessível (contraste adequado, fontes legíveis, navegação por teclado).

O que este prompt especifica?

Produto → nome → plataforma → estrutura → conteúdo → interação → animação → acessibilidade.

15 · Exemplo prático · Leitura crítica

Um prompt não substitui UX.

O prompt define

  • o que construir;
  • componentes;
  • comportamento;
  • requisitos visuais;
  • acessibilidade básica.

A equipa ainda decide

  • quem utiliza;
  • quais contactos são confiáveis;
  • o que acontece após o SOS;
  • como evitar acionamentos acidentais;
  • como validar.
Regra do hackathon: IA pode gerar o protótipo. A equipa continua responsável pelo problema, contexto, UX e validação.

17 · Transição para o hackathon

Agora façam o mesmo com o vosso problema.

Problema real → utilizador → oportunidade → fluxo → prompt → protótipo → teste.
Pergunta final:

“Que decisão de design estou a tentar tornar testável com este protótipo?”

O protótipo é o início da aprendizagem — não a prova de que a solução está certa.
